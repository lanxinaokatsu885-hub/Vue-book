# 代换班记录周次修改说明文档

## 一、问题描述
由于排班员的疏忽，原本应该是第五周的排班记录被错误地标记为第六周，导致：
- 排班数据存储在第六周
- 代换班记录也标记为第六周
- 系统中出现了错误的周次数据

## 二、解决方案
需要执行以下操作来修正这个问题：
1. 将第六周的排班数据迁移到第五周
2. 将数据库中所有第六周的代换班记录改为第五周
3. 删除第六周的冗余数据

## 三、操作步骤

### 步骤 1：迁移排班数据
1. **登录服务器**：使用 SSH 登录到服务器
2. **进入备份目录**：
   ```bash
   cd /var/www/book/beifen
   ```
3. **复制第六周备份文件**：
   ```bash
   cp 第六周.json 第五周.json
   ```
4. **修改周次信息**：
   ```bash
   sed -i 's/"week":"第六周"/"week":"第五周"/g' 第五周.json
   ```
5. **恢复第五周数据**：
   ```bash
   curl -X POST http://localhost:3000/api/save-schedule \
     -H "Content-Type: application/json" \
     -d @./第五周.json
   ```
6. **验证恢复结果**：收到 `{"code":200,"msg":"排班数据保存成功","data":null}` 表示操作成功

### 步骤 2：修改代换班记录周次
1. **登录 MySQL 数据库**：
   ```bash
   mysql -u paiban_user -p paiban_system
   ```
2. **更新换班记录表**：
   ```sql
   UPDATE swap_requests SET week = '第五周' WHERE week = '第六周';
   ```
3. **更新代班记录表**：
   ```sql
   UPDATE substitute_requests SET week = '第五周' WHERE week = '第六周';
   ```
4. **退出 MySQL**：
   ```sql
   EXIT;
   ```

### 步骤 3：清理第六周数据
1. **删除第六周备份文件**：
   ```bash
   rm /var/www/book/beifen/第六周.json
   ```
2. **删除数据库中的第六周排班数据**：
   ```bash
   mysql -u paiban_user -p paiban_system -e "DELETE FROM schedule_data WHERE JSON_UNQUOTE(JSON_EXTRACT(data, '$.week')) = '第六周';"
   ```

## 四、验证方法
1. **检查排班数据**：
   - 访问排班系统主页面
   - 切换到第五周，确认数据已正确显示
   - 切换到第六周，确认数据已被删除

2. **检查代换班记录**：
   - 在主页面查看代换班记录
   - 确认所有记录的周次已正确显示为第五周
   - 验证记录内容是否完整

## 五、注意事项
1. **操作前备份**：建议在执行操作前先备份数据库，以防万一
2. **服务器状态**：确保 Node.js 服务器正在运行
3. **权限问题**：确保有足够的权限执行文件操作和数据库操作
4. **数据一致性**：确保排班数据和代换班记录的周次保持一致
5. **验证结果**：操作完成后一定要验证结果，确保数据正确迁移

## 六、技术原理
1. **备份文件修改**：通过复制和修改 JSON 文件实现排班数据的周次变更
2. **API 恢复**：使用 `save-schedule` API 将修改后的数据保存到数据库
3. **数据库更新**：通过 SQL 语句批量更新代换班记录的周次字段
4. **数据清理**：删除冗余的第六周数据，保持系统数据的整洁

通过以上操作，可以快速、准确地修正周次错误问题，确保系统数据的正确性和一致性。
